# Повторная проверка библиотеки v0.2

14 сентября 2026. Статус эффективности сайтов: **не установлена**. Эта работа проверяет достоверность инструкций и инструменты подготовки, не заменяет генерацию, браузер и человеческую приёмку.

## Найдено и исправлено

1. **Синхронизация ломала проверку.** Файлы сохранились, но завершающий LF исчез: добавление одного LF восстанавливало прежние хэши всех пяти входов baseline. Содержание не менялось. Сборщик теперь стабильно нормализует текст перед объединением и хэшированием; формат манифеста повышен до v2. Изменения внутри текста по-прежнему обнаруживаются.
2. **Два внешних гайда нельзя было автоматически считать надёжными.** Найдены неверные единицы крупного текста WCAG, несходящийся пример clamp и ошибочная версия поддержки Safari. Карточки сохранены с причинами, но исключены из пакета. Вместо них — Carbon, MDN и web.dev. Подробные источники: [ресерч v0.2](../resources/research-v0.2.md).
3. **Не было воспроизводимых отрицательных проверок.** Прежние 22 случая были разовым запуском. Теперь команда selfcheck повторяет проверки маршрутизации, формата, нормализации Prism и запрета преждевременной приёмки.
4. **Пустой отчёт не защищал от ложного true.** Добавлен check-run: для принятого раунда нужны завершённая генерация, соответствующий манифест, T01–T12 pass, оценки и файлы браузерного/человеческого свидетельства. Истинность этих файлов валидатор установить не может.
5. **Инструкции заставляли делать лишнее.** Убраны обязательные две концепции и поиск ровно трёх дефектов. Альтернативы нужны при неопределённости; исправляются реальные проблемы.
6. **Метрика успеха была недостаточно определена.** Протокол теперь заранее фиксирует основной исход, сохраняет неудачные/незавершённые попытки, различает первый и второй результат и учитывает чтение источников.
7. **Доступность была слишком общей.** Добавлены конкретные проверки размеров целей, перекрытого фокуса, увеличения/интервалов текста, состояния кнопок и видов движения. Разделены требования A/AA/AAA и наши более строгие условия брифа.
8. **История могла читаться даже при проверке только исходников.** В отдельном прогоне агент обнаружил конфликт ограничения контекста с validate --sources-only. Исключено чтение reports в этом режиме и добавлена проверка этого ограничения.

## Проверки

Финальный запуск: 44 контрольных случая selfcheck прошли; полный validate и проверка шаблона check-run прошли; формат скилла проверен quick_validate. В каталоге 15 карточек (12 reviewed, 1 candidate, 2 retired), в profile выбраны 8 справок. Пакеты: baseline 849, core 2229, profile 3583 слова при ограничении 4500. Подсчёт слов не является подсчётом токенов или доказательством оптимального контекста.

Результат повторяемых проверок: [selfcheck-v0.2.json](selfcheck-v0.2.json). Для самостоятельного запуска:

```sh
python web-library/tools/library.py.txt validate
python web-library/tools/library.py.txt selfcheck
python web-library/tools/library.py.txt check-run --report web-library/experiments/run-template.json
```

selfcheck использует синтетический «принятый» отчёт только в памяти для проверки формата. Он не является созданным сайтом или реальным свидетельством успеха. Проверка нормализации моделирует LF/CRLF в памяти; следующую реальную синхронизацию всё равно нужно проверить.

Дополнительно проведены [два ограниченных выполнения скилла](forward-runs-v0.2.md). Первое действительно пересобрало пакет; второе корректно обозначило пробел образовательного профиля. Это проверка поведения инструкции, а не качества дизайна. Арифметический разбор ошибочного примера сохранён в `web-library/reports/source-checks-v0.2.json`.

Старый сайт и его сборщик не исправлялись в рамках задачи: SHA-256 всех семи файлов совпали с прежним local-audit.json. Предыдущий отчёт об отличии экспорта по переводам/пустым строкам остаётся отдельным наблюдением, не дефектом новой библиотеки.

## Что нельзя объявлять выполненным

Нет независимого A/B сайтов, визуальных оценок, браузерного запуска, проверки реальной плавности или гарантии результата за два запроса. Доступность браузера/Playwright повторно проверена — в доступных командах/модулях они отсутствуют. Зависимости не устанавливались. Полный аудит всех внешних репозиториев не проводился; исследовались конкретные файлы и первичные документы.

Следующий полезный шаг — исполнить один pilot по fold-profile в согласованной среде и посмотреть реальный экспорт. После этого сравнивать core/profile, а не расширять список источников ради объёма.
