# Контракт среды: freebuff-local

Проверено 2026-09-16 в текущей рабочей копии. Это наблюдение, а не вечное свойство платформы:
перед новым запуском прогнать `python web-library/tools/probe_env.py.txt` и сверить.

Прошлый контракт (`environments/prism-offline.md`) описывал другую рабочую копию. Его утверждение
«браузера нет, Playwright не искать и не устанавливать» здесь **неверно**: оно годами попадало в
каждый собранный пакет и запрещало исполнителю ровно те проверки, которые дают качеству больше
всего. Замер ниже — причина, по которой этот файл существует.

## Доступно

Проверено запуском, не чтением документации:

- Node.js v22.23.1, npm/npx 12.0.2, bun 1.3.8, Python 3.13.15, git 2.49.0.
- Playwright 1.63.0 и `@playwright/test` 1.63.0 установлены локально в проекте; `@axe-core/playwright`
  4.13.0; vite 8.3.0; TypeScript 7.0.2.
- Браузеры Playwright скачаны: `chromium-1223`, `chromium-1243`, `chromium_headless_shell-1243`,
  а также `ffmpeg-1011`. `chromium.launch()` работает, версия браузера 153.0.8010.12.
- Системные браузеры: Chrome и Edge.
- Эмуляция `prefers-reduced-motion`, размеров окна, `deviceScaleFactor`; скриншоты и запись консоли
  из Playwright работают.
- Панель предпросмотра: отдаёт DOM и дерево доступности надёжно, скриншот — обычно, но при
  отсутствии композитинга webview может отказать; после перезагрузки страницы работает.
- Сеть наружу доступна: `registry.npmjs.org` и `github.com` отвечают 200. `git clone` и установка
  зависимостей технически возможны.
- Локальный статический сервер (`python -m http.server`, `vite preview`) для просмотра готовой сборки.

Проверенный пример полного гейта: `cd "Test 1" && npm run check` — сборка, бюджет бандла и 15
Playwright-тестов, включая axe (serious/critical) и режим уменьшенного движения, пройдены целиком
за 49 секунд.

## Недоступно

- Гарантии, что перечисленное сохранится в следующей сессии: это наблюдение одной даты.
- Настройки операционной системы (системное уменьшенное движение) нельзя переключить из кода;
  подменяется значение `matchMedia` до инициализации скриптов — это эмуляция, а не настройка ОС.
- Реальные мобильные устройства, инерция и «резинка» прокрутки, адресная строка Safari.
- Сохранение видео и трасс панели предпросмотра в файл: панель отдаёт снимок в интерфейс, но не
  гарантирует запись. Для видео использовать покадровую запись из самого движка страницы.

## Правила

1. Писать только внутри workspace, относительными путями. Чужие исходники и библиотеку не менять,
   если это не задача о библиотеке.
2. Исходники — обычные `.html`, `.css`, `.js`, `.mjs`; зависимости обосновывать конкретной
   потребностью. Массовые обёртки `.txt` здесь не нужны.
3. Готовый результат должен открываться без сети: один файл с включёнными стилями и скриптами либо
   сборка, не обращающаяся к внешним адресам. Проверять это снятием журнала запросов.
4. Браузерные проверки обязательны, если браузер доступен. Оставить пункт `not_run` можно только
   с указанием причины, почему он не выполнялся именно здесь.
5. Не выдавать статический разбор, парсинг или моделирование DOM за просмотр браузером.
   Скриншот и «axe прошёл» не доказывают ни доступность целиком, ни качество дизайна.
6. Доказательства (снимки, вывод проверок, трассы) хранить в каталоге запуска. В библиотеку и в
   пакеты они не переносятся.
7. Зависимости, скачанные для проверки, не становятся частью результата без отдельного решения:
   автономный экспорт и рабочий стек — разные вещи.

## Каталог сдачи

Результат писать только в `trial-output/<brief>-<arm>/`:

- исходники (`index.html`, `styles.css`, `main.js` и модули, если они есть);
- сборка автономного экспорта, если она есть, и её точная команда;
- `README.md` с командами запуска, сборки и просмотра;
- `REPORT.md` с выбранным направлением, статусами проверок `pass / fail / not_run`, доказательствами
  и честным перечнем того, что не проверено;
- каталог доказательств запуска (снимки, вывод гейта, кинолента), если они получены.

Если каталог занят предыдущим запуском, не перезаписывать его: выбрать новый суффикс повтора и
записать путь. Не создавать новый репозиторий и не делать commit из задачи исполнения.
