# Модуль: движение при прокрутке

ID: `scroll-motion`. Цель: безопасное улучшение статического рассказа. Отдельно выбрать механизм; наличие слова scroll не означает необходимость библиотеки.

## Дерево выбора

| Потребность | Первый кандидат | Когда сменить |
| --- | --- | --- |
| Обычная навигация, чтение | Нативная прокрутка, CSS | Не менять без конкретной проблемы |
| Разовое появление | IntersectionObserver + CSS | Если требуется непрерывный прогресс, это другой механизм |
| Прогресс/простое преобразование | CSS scroll/view timeline как enhancement | При отсутствии подтверждённой поддержки дать статический вариант |
| Дискретные стадии/нестандартная геометрия | Небольшой JS, событийный requestAnimationFrame | Если управление становится существенно сложнее |
| Сложная синхронизированная последовательность | GSAP ScrollTrigger как кандидат | Только в среде с доступной поставкой и проверкой зависимости |

Основания: карточки `mdn-intersection`, `mdn-scroll`, `gsap-scrolltrigger`. CSS-ветка не объявляется совместимой со всеми браузерами. IntersectionObserver сообщает изменения пересечения, а не точную непрерывную координату прокрутки. ScrollTrigger предоставляет scrub/pin, но не нужен по умолчанию.

При CSS timeline проверять конкретное свойство и функцию, объявлять `animation-timeline` после shorthand `animation`, иначе shorthand сбросит timeline. `@supports` проверяет распознавание синтаксиса, не фактическую плавность или правильную геометрию. Карточка `mdn-animation-timeline` содержит отдельные первичные данные совместимости.

Карточка GSAP намеренно не входит в первый пакет: это отложенная альтернатива, а не недостающая инструкция для выполнения. Её документация нужна только при отдельном расширении среды; первый тест выполнять без неё.

## Контракт состояний

Базовая разметка видима. Скрывать элементы для reveal только после успешной инициализации; при сбое возвращать видимость. Не оставлять смысловую информацию только в canvas/SVG без текста.

Определить состояния: обычное, системное уменьшение движения, ручное уменьшение, отсутствие API, узкий/короткий экран. Для первого профиля эффективное уменьшение движения = системное ИЛИ ручное; ручное включение не отменяет системное предпочтение. Не называть настройку «статика», если она отключает лишь часть эффектов.

В уменьшенном режиме отключить ненужные перемещения, автоматическое плавное листание и закрепление сцены; показать все стадии статически. Кнопки и смысловые действия продолжают работать. Системную настройку читать до включения эффектов и отслеживать её изменения. Основание API: карточка `mdn-reduced-motion`; конкретный контракт ИЛИ — правило нашего профиля.

Не подменять отключение scroll-driven эффекта установкой duration=0.01ms: временная длительность не разрывает связь с прокруткой. Явно отключить нужные CSS-анимации/таймлайны и JS-обновления, восстановить статические transform/opacity, не полагаться на animationend для доступности текста. Нативную прокрутку не отключать.

Для toggle со стабильным названием отражать состояние через aria-pressed; если кнопка названа следующим действием, не добавлять несогласованное pressed-состояние. Не объявлять каждое изменение скролл-прогресса через aria-live. Декоративные дубли SVG скрывать от accessibility tree, смысловую схему снабдить доступным названием и текстовым объяснением.

## Геометрия и жизненный цикл

Прогресс ограничить диапазоном 0…1, защитить нулевую длину сцены. Проверить границы стадий в обе стороны. Отделять измерения от записи стилей; не опрашивать всю страницу каждый кадр без причины. Пересчитать геометрию после изменения размеров/контента. Снимать обработчики и наблюдатели, если модуль повторно инициализируется или отключается.

Закрепление включать только когда сцена помещается по высоте и ширине. Порог выбирать по фактическому контенту, не копировать числа старого сайта. При смене режима сохранять положение читаемого содержимого; не прокручивать пользователя принудительно к началу.

По умолчанию предпочитать transform/opacity для перемещений и появления. Другие свойства не являются автоматически ошибкой, но требуют причины и измерения layout/paint. Не добавлять will-change всему документу и не обещать FPS по списку свойств. Источник: `webdev-animation`.

## Проверить

Начало/середина/конец, обратная прокрутка, быстрая прокрутка, resize посреди сцены, короткий экран, отключённый JS, смена reduced-motion на загрузке и во время чтения. Парсинг JS не закрывает ни одну визуальную проверку.
