## 2. Бриф (по `experiments/briefs/fold.json`)

- Аудитория: русскоязычный взрослый без опыта бумажного моделирования, который хочет попробовать
  небольшое творческое занятие.
- Цель: понять идею мастерской и перейти к первой самостоятельной пробе прямо на странице.
- Главное действие: ссылка «Попробовать первый сгиб» ведёт к разделу с тремя шагами; они доступны
  и без JavaScript.
- Тон: тактильный, ясный, внимательный к форме; не детский праздник и не технологический SaaS.
- Обязательное содержание: четыре блока фактуры из брифа, дословно.
- Обязательное взаимодействие: кнопка «Показать сгиб / Вернуть плоскость» управляет отдельной от
  скролл-сцены схемой и её доступной подписью; повторное действие возвращает плоскость; прокрутка не
  меняет ручной выбор; без JS есть статическое объяснение.
- Обязательные режимы движения: явный переключатель уменьшения движения; эффективное уменьшение =
  системное ИЛИ ручное; в этом режиме состояния схемы меняются мгновенно, смысловые действия
  работают, прокрутка остаётся нативной; без JS рассказ и навигация читаются статически.
- Не делать: регистрация, оплата, расписание, 3D/WebGL, отзывы и выдуманные цифры.

## 3. Выбранные инструменты (минимум, достаточный для этой среды)

| Решение | Что взято | Почему |
| --- | --- | --- |
| Разметка и стили | один статический `index.html` + `styles.css` | профиль `scroll-story` прямо ограничивает первый тест; больше ничего не требуется |
| Скрипты | один классический `main.js`, без модулей и зависимостей | классический скрипт открывается и по `file://`, в отличие от `type="module"` |
| Библиотеки | нет ни одной runtime-библиотеки, шрифта, CDN и внешней сети | требование сценария «три состояния» покрывается рукописной геометрией и небольшим JS |
| Графика | оригинальный inline SVG, пять фигур: герой, три кадра сцены, схема сгиба | фотографий и внешних шрифтов нет по брифу |
| Сборка | `build.mjs` на стандартной библиотеке Node | нужен воспроизводимый автономный файл `dist/index.html` |
| Проверка | `scripts/check.mjs` на стандартной библиотеке Node | даёт статические доказательства вместо недоступного браузера |
| Пакетный менеджер, сборщик, TS, React | не добавлены | в репозитории нет `package.json`, а один документ не окупает конвейер |

Технический стек выбран минимально достаточным: HTML, CSS, классический JS, Node только для сборки и
проверок. Внешние ассеты не добавлены ни одного, поэтому вопрос условий использования не возникает.

## 4. Доступные и недоступные способы проверки в этой среде

Доступно (проверено в шелле):

- Node.js v22.23.1, npm, bun 1.3.14, Python 3.10.12, git.
- Локальный HTTP-сервер (`python3 -m http.server`) для ручного просмотра человеком.
- Статический разбор: уникальность `id`, разрешение внутренних якорей и `aria`-ссылок, наличие
  доступных имён, отсутствие внешних ссылок, измерение контраста по формулам WCAG, размер и
  SHA-256 артефакта, повторяемость сборки.
- Запуск чистых функций `main.js` в Node (границы стадий, тексты подписи и кнопки).

Недоступно (не запускалось и не устанавливалось):

- Браузер: Chromium, Chrome, Firefox в `PATH` отсутствуют, кэш Playwright пуст, Playwright не
  установлен. Поэтому все визуальные, клавиатурные и reduced-motion проверки в браузере — `not_run`.
- Команды `freebuff-preview` и `freebuff-deploy` в этой рабочей копии отсутствуют, поэтому превью и
  деплой не запускались; вместо них в `README.md` дана точная команда локального запуска.
- Скриншоты: получить не удалось (нет браузера). Вместо них честно указан ручной сценарий просмотра.

Браузер не устанавливался сознательно: `checks/review.md` запрещает искать и ставить Playwright для
обхода контракта задания, а `NODE`-проверки не подменяют просмотр браузером.

## 6. Принятые допущения (некритичные, без вопроса пользователю)

- Фактура из брифа — вымышленная мастерская; сайт явно помечен как демонстрационный.
- В разделе «Сначала попробуйте» текст брифа содержит четыре предложения, а главное действие обещает
  «три шага». Предложения объединены в три шага без изменения слов (шаг 2 содержит складывание и
  поиск линии), фраза «Это исследование формы, не экзамен на точность» вынесена отдельной заметкой.
- Визуальные референсы пользователем не утверждены, поэтому направление ниже — гипотеза, а не
  совпадение с неизвестным вкусом.

## 7. Направление (design-intent, гипотеза)

- Идея: страница как технический лист мастерской — тёплая бумага, графитовый текст, один
  вермильоновый акцент на линии сгиба; сквозной мотив — сгиб, который повторяется в разделителях,
  нумерации панелей и SVG.
- Первый экран: крупный заголовок «Из плоскости — в форму», пояснение и главное действие; справа —
  схема листа в момент подъёма одной половины с обозначением прежнего положения.
- Роли шрифтов: засечный системный для заголовков (редакционный, тактильный), системный без засечный
  для текста и интерфейса, моноширинный только для номеров панелей и латинских меток.
- Сетка: одна колонка с максимальной шириной текста около 34rem, поля `clamp(1.1rem, 4vw, 3rem)`,
  вертикальный ритм через `clamp()` с привязкой к высоте экрана, чтобы короткий экран не терял CTA.
- Графика: пять inline SVG; каждый рисунок объясняет состояние листа, у всех есть текстовый эквивалент
  в разметке, декоративные дубли скрыты от дерева доступности.
- Один принцип движения: лист меняет состояние вместе с прокруткой в разделе «Три состояния листа»;
  в уменьшенном режиме все три кадра показаны статически, закрепление выключено.
- Сознательно исключено: скролл-снап, перехват колеса, кастомный курсор, WebGL, появление каждого
  блока по отдельности, карточки-сетки, тёмная тема, декоративный шум-текстура.
